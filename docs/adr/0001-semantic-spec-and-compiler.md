## 背景

参考项目让大语言模型生成简化的 Excalidraw 元素骨架，再由应用代码补全绑定和字段。让模型直接生成完整 `.excalidraw` 文件虽然不需要转换步骤，但容易产生无效引用、不稳定 ID、不准确的文本尺寸和脆弱的格式字段。

需要在无 Mermaid、无第三方运行时依赖的前提下，提高生成结果的确定性和可测试性。

## 决策

采用语义化 DiagramSpec 作为 Agent 与运行时之间的契约，并实现无第三方依赖的确定性 Node.js 编译器。

Agent 负责理解用户意图和产出语义；编译器负责布局、ID、几何、绑定、Excalidraw 字段和质量检查。相同 DiagramSpec 与 seed 应产生相同结果。

## 备选方案

| 方案 | 取舍 |
|---|---|
| 模型直接生成完整文件 | 实现最少，但难以验证、迁移和稳定修改。 |
| 复用参考项目元素骨架 | 可借鉴，但仍把大量坐标与元素细节交给模型。 |
| 使用官方 Excalidraw npm 包 | 文本度量和格式兼容更强，但增加依赖、浏览器环境要求和版本耦合。 |

## 影响

- 可以独立测试语义、布局和序列化。
- 可以对 DiagramSpec 做显式版本迁移。
- 需要维护自有布局器、格式快照和文本尺寸启发式。
- 不包含真实浏览器渲染，视觉检查仍有近似误差。
