## 背景

Drawing Master 最初只将 DiagramSpec 编译为 Excalidraw。项目需要增加 Mermaid 和 draw.io，同时保持确定性输出、可测试性和用户未指定格式时的显式选择。

三种格式的编辑模型并不相同。Excalidraw 和 draw.io 保存显式几何，Mermaid 则由渲染器决定布局。现有 Excalidraw 编译器还可以透传未知元素和样式，而整体重新生成 Mermaid 或 draw.io 会覆盖文件内的手工调整。

## 决策

DiagramSpec 保持格式中立，并作为受管图表文档唯一的语义事实来源。同一文档身份可以关联多个格式产物，各产物只承诺语义等价，不承诺视觉等价。

Excalidraw 继续支持保留未知内容的原位修改。Mermaid 和 draw.io 首版采用受管重编译：更新前比较上次编译哈希，发现手工变化时停止并要求用户决定，不静默覆盖。

同步默认更新全部受管格式。用户明确指定格式时只检查和更新所选产物，其他产物保持不变；若规格已经变化，它们通过产物层规格哈希与文档层规格哈希不一致呈现为 `stale`。

Manifest 关联丢失后不得扫描文件名或反向解析语义来猜测身份。恢复必须由用户显式提供 DiagramSpec 和自产产物，并要求每个产物内嵌的 `documentId` 与 `specHash` 同时匹配；恢复只重建管理状态，不重写产物。

运行时保持无第三方依赖。Mermaid 面向版本 10 及以上的安全语法子集，不适合原生语法的图表明确降级为 flowchart。draw.io 输出未压缩、单页的 `.drawio` XML。外部 Mermaid 和 draw.io 只校验系统支持的安全子集，不提供通用导入或非破坏性修改。

用户未明确指定输出格式时，Agent 必须询问并允许多选。CLI 不再默认 Excalidraw，缺少格式信息时拒绝执行。

## 备选方案

| 方案 | 取舍 |
|---|---|
| 为每种格式维护独立语义模型 | 可以充分利用格式特性，但会造成同一图表语义分叉和重复维护。 |
| 将格式配置写入 DiagramSpec | 实现直接，但污染格式中立的领域模型并增加迁移成本。 |
| 引入 Mermaid 和 XML 第三方解析器 | 外部文件兼容更广，但扩大安装、供应链和版本耦合范围。 |
| 静默覆盖自产文件 | 实现最少，但会丢失用户手工编辑，不能称为安全更新。 |
| 所有 Mermaid 类型只用 flowchart | 兼容简单，但损失时序、状态和类图等成熟原生语义。 |

## 影响

- Manifest 必须记录同一文档的多个产物、规格哈希和产物哈希。
- 多格式同步需要冲突预检、临时写入和失败回滚。
- 选择性同步只对所选格式执行冲突处理，未选格式不阻塞本次同步。
- 三种格式都必须内嵌可校验的文档身份与规格哈希，供显式身份恢复使用。
- Mermaid 质量门只能保证支持子集的结构和语义，不能声称完成视觉检查。
- draw.io 首版不支持压缩 payload、多页文档或外部文件无损修改。
- DiagramSpec v1 无需因新增输出格式升级。
- CLI 缺少格式时不再沿用旧版 Excalidraw 默认行为。
