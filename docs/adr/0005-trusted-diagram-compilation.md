> 决策：在可编辑格式边界内引入严格规格、统一诊断、确定性几何和可验证交付。

## 背景

多格式编译已经能从同一 DiagramSpec 生成 Excalidraw、Mermaid 和 draw.io，但 v1 规格宽松、视觉诊断缺少统一证据，CLI 也不能在不写入工作区的情况下完整预检交付。

## 决策

- DiagramSpec v2 采用严格字段和类型专属语义；v1 保持编译兼容，通过 `migrate` 显式升级。
- `check` 在内存中编译所选格式并运行规格、格式、共享几何和可选源码证据检查，不创建运行状态。
- 诊断统一包含代码、严重性、消息、目标、证据和受支持修复动作。
- `standard` 保留可交付视觉警告；`showcase` 将几何和视觉警告提升为阻断错误。
- Excalidraw 和 draw.io 共享按稳定身份分配的端口与正交路线；Mermaid 仍只承诺安全语义子集，不声称验证目标渲染器视觉结果。
- 成功写入后返回最终文件 SHA-256 和 UTF-8 字节数，并在覆盖提交前复核原内容哈希。
- 架构图可声明本地 Git 源码证据。验证器只读取匹配 origin 的完整提交和 blob，不联网、不生成主动链接。

## 后果

v2 作者必须提供明确的节点和关系 kind，并满足时序、状态、ER、甘特图、时间线和数据流图语义。严格契约增加了作者成本，但错误能在写入前定位，产物也具有可复核回执。

本决策不引入交互式 HTML、浏览器 Viewer、动画、PNG/SVG/WebM、品牌图标、联网更新或 Mermaid/draw.io 反向解析。产品边界以 [`../../README.md`](../../README.md) 和 [`../../CONTEXT.md`](../../CONTEXT.md) 为准。
